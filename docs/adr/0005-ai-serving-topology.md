# ADR 0005: AI 추론 서버 배포 위치

- 날짜: 2026-10-03
- 상태: Pending (보류)
- 구현 상태: AI 저장소 `main`의 HTTP 추론·등록 음성 수신·학습 작업 경로는 로컬 코드로 구현됐다. AI 서비스용 컨테이너 이미지·모델 아티팩트 배포 경로·AWS 추론 환경은 아직 없다. 운영자는 GPU 사용을 가급적 피하고 AWS 크레딧 내에서 서버를 짧게 켜서 테스트할 계획이다.

## 배경

BE는 `AI_SERVER_BASE_URL`로 HTTP AI 서버를 호출한다. 현재 Infra는 BE용 EC2 `m5.large` 한 대만 정의한다. 갱신된 AI 저장소는 `openai/whisper-small`의 고정 리비전과 선택적 사용자별 LoRA 어댑터를 사용한다. 학습된 어댑터와 데이터는 Git에 포함하지 않으며, 기본 모델만 사용하는 것도 정상 상태다. AI 서버는 모델을 메모리에 올려 추론한다. 노트북 CPU 추론 기록은 있지만 AWS `m5.large`에서 BE와 동시 실행한 측정은 없다.

AI의 사용자별 어댑터 학습 경로는 구현됐지만, 학습기는 GPU가 없으면 기본적으로 실행을 거부한다. `ALLOW_CPU_TRAIN=1`은 CPU 학습을 허용하는 짧은 테스트용 설정이며 운영 성능은 검증되지 않았다. 따라서 GPU를 사용하지 않는 이번 인프라 실증 범위는 **CPU 추론과 BE 연결**부터 잡는다.

## 검토한 방식

1. **BE 이미지에 AI 코드를 합침:** 배포 단위는 하나지만 Java와 Python·PyTorch 의존성, 이미지 크기, 모델 교체 주기가 함께 묶인다.
2. **별도 AI 이미지, 같은 EC2:** 기존 BE 이미지와 AI 이미지를 각각 실행한다. 초기 AWS 자원은 적지만 BE `m5.large`의 CPU·8 GiB 메모리를 공유한다. 두 컨테이너는 전용 Docker 네트워크에서 통신하고 AI 포트는 인터넷에 게시하지 않는다.
3. **별도 AI 이미지, 별도 EC2:** CPU·메모리 또는 GPU를 AI 요구에 맞춰 선택하고 BE 보안그룹에서만 AI 포트에 접근하도록 한다. 인스턴스·스토리지·네트워크 비용과 Terraform·SSM 배포 경로가 추가된다.

## 현재 권장 진행 순서

AI를 BE 이미지에 합치지 않고 **독립된 이미지**로 만든다. 모델 아티팩트의 보관·배포 권한과 실행 의존성을 확정한 뒤, 먼저 같은 EC2의 별도 컨테이너로 부팅·계약·메모리·응답시간을 측정한다. 기존 `m5.large`에서 수용되지 않으면 인스턴스 크기 변경을 먼저 검토하고, 그래도 분리가 필요할 때 AI 전용 CPU EC2를 검토한다. GPU는 현재 계획에 포함하지 않는다. EC2 안에서 소스를 빌드하는 방식은 재현성과 배포 시간을 악화시키므로 이미지 빌드는 CI에서 수행한다.

현재는 성능·비용 자료가 부족해 최종 위치를 확정하지 않는다. 같은 EC2에서 실행하려면 Docker 네트워크와 AI 컨테이너 배포를 추가하고 `AI_SERVER_BASE_URL`을 그 네트워크의 AI 서비스 주소로 설정해야 한다. 별도 EC2로 옮기면 VPC 내부 주소·보안그룹·접근 경로를 Terraform에 추가해야 한다. 두 방식 모두 현재 SSM 배포 코드에는 아직 구현되지 않았다.

테스트 후 EC2만 중지해도 EBS·Elastic IP 비용은 남고, 현재 Terraform의 RDS·ElastiCache는 별도 과금된다. ElastiCache는 사용하지 않으면 삭제해야 비용이 멈춘다. 비용 실증은 EC2 한 대뿐 아니라 세 Terraform 레이어 전체를 기준으로 한다.

## Accepted 전환 조건

1. AI 이미지의 빌드와 모델 아티팩트 전달 경로가 정해지고, 사용 권한·보관 범위가 확인된다.
2. 실제 CPU EC2에서 BE와 AI를 함께 실행해 메모리, CPU, 시작 시간, 요청 지연을 측정한다. 모델 추론과 사용자별 학습의 결과를 구분한다.
3. 측정 결과에 따라 AI 인스턴스 분리 여부를 결정하고 Terraform·배포 스크립트·운영 문서에 반영한다.
