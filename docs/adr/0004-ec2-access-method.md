# ADR 0004: 앱 EC2 접속·배포 방식 선택

- 날짜: 2026-10-02
- 상태: Pending (보류)
- 구현 상태: SSH 접속 설정은 Terraform과 운영 가이드에 남아 있다. SSM용 EC2 역할·배포 스크립트·수동 워크플로를 작성했지만 아직 적용·실제 배포 검증 전이다.

## 배경

현재 Terraform은 앱 EC2에 기존 키 페어를 지정하고, 보안그룹에서 지정한 IP의 SSH 22번 포트를 허용한다. [운영 가이드](../GUIDE.md)는 이 키로 앱 EC2에 직접 접속해 환경변수를 설정하는 절차를 안내한다. 별도 Bastion 호스트는 정의되어 있지 않다.

CD에서는 GitHub Actions가 EC2에 배포 명령을 전달해야 한다. SSM Run Command 방식의 구현이 시작됐지만 실제 EC2 생성·관리 대상 등록·배포 명령 실행은 확인되지 않았다.

## 검토 중인 방식

- **SSH:** 기존 키 페어와 제한된 IP의 22번 포트를 사용해 앱 EC2에 직접 접속한다. 현재 코드와 가이드에 입력값과 접속 명령이 있다.
- **SSM:** EC2 Instance Profile에 SSM 관리 권한을 부여하고, SSM Agent를 통해 배포 명령을 실행한다. 이 경로를 먼저 구현하고 실제 배포를 검증한다.

## 보류한 결정

최종 접속·배포 방식을 아직 확정하지 않는다. 현재 구현의 기본 배포 경로는 SSM으로 잡고 실제 동작을 검증한다. 그동안 기존 SSH 키 페어 요구사항과 22번 포트 설정을 유지한다. 이 문서의 `Pending`은 SSM의 실제 운영 검증이 아직 끝나지 않았다는 뜻이다.

## Accepted 전환 조건

1. Terraform으로 만든 EC2가 Systems Manager 관리 대상에 등록되고, 해당 EC2의 SSM Agent와 역할 권한이 정상 동작한다.
2. Infra 배포 워크플로가 SSM으로 대상 EC2에 명령을 보내고 실행 결과를 확인한다. GHCR 이미지 배포와 애플리케이션 상태 확인까지 동작한다.
3. 검증 결과에 따라 SSH를 계속 둘지 결정하고, 키 페어·22번 포트 설정과 운영 문서를 선택한 방식에 맞게 정리한다.

위 조건을 충족해 최종 방식을 확정하면 이 ADR을 `Accepted`로 변경하고 결정 내용과 검증 근거를 기록한다.
