# 사양·비용과 확정 절차

현재 사양은 **데모 사양**이다. 실서비스가 아니라 시연·테스트용이므로 AI가 메모리 부족으로 죽지 않는 것을 우선하고, 비용은 사양이 아니라 **켜두는 시간**으로 줄인다. 단가는 AWS Pricing API로 조회한 서울 리전 On-Demand 값(2026-10-30)이다. 실제 청구액은 프로젝트 계정의 Cost Explorer로 확인하고, 다르면 이 문서를 고친다.

## 현재 사양 (데모)

| 리소스 | 변수 | 유형 | vCPU / 메모리 | 스토리지 | $/시간 | 근거와 한계 |
|---|---|---|---|---|---|---|
| AI | `ai_instance_type` | `m7i-flex.large` | 2 / 8 GiB | root 40 GiB + 데이터 20 GiB | 0.1177 | AI팀 실측은 **추론 3건 기준 1.67 GiB**(arm64, 4GB 제한)뿐이고 학습 중 메모리는 측정된 적이 없다. 2 GiB(`t3.small`)로는 여유가 없다. Flex 인스턴스는 CPU 크레딧이 없어(기준 40%, 필요 시 100%) 긴 CPU 학습에도 성능이 떨어지지 않는다 |
| BE | `be_instance_type` | `t3.small` | 2 / 2 GiB | root 30 GiB | 0.026 | 배포 스크립트에 JVM 메모리 옵션이 없어 힙은 기본값(메모리의 25%, 약 512 MiB)이다. 데모 트래픽에는 충분할 것으로 보고 유지한다. 측정 후 결정 |
| FE | `fe_instance_type` | `t3.small` | 2 / 2 GiB | root 30 GiB | 0.026 | nginx 정적 파일과 Caddy. 측정되지 않았다 |
| RDS MySQL | `rds_instance_class` | `db.t3.micro` | 2 / 1 GiB | gp3 20 GiB | 0.026 | 데모 DB 부하는 작다. 이미 가장 작은 급이다 |
| ElastiCache Redis | `redis_node_type` | `cache.t4g.micro` | 2 / 0.5 GiB | – | 0.024 | 데모에서 Redis 사용량은 작다. 이전 `cache.m5.large`($0.191)는 시간당 요금의 62%였다 |
| 공인 IPv4 × 3 | – | FE Elastic IP, BE·AI 자동 할당 | – | – | 0.015 | 사용 중이든 유휴든 개당 $0.005/시간 |
| **합계** | | | | | **0.2347** | 이전 0.310 |

### 사양 변경 이력

| 시점 | BE | AI | RDS | Redis | $/시간 | 비고 |
|---|---|---|---|---|---|---|
| 설계값 | `m5.large` | `m5.xlarge` | `db.r5.large` | `cache.m5.large` | 0.871 | 2026-10-03 apply에서 Free 플랜 제한(`FreeTierRestrictionError`)으로 EC2·RDS가 거부됨 |
| 2026-10-03 | `t3.small` | `t3.small` | `db.t3.micro` | `cache.m5.large` | 0.310 | apply를 통과시키기 위한 임시 축소 |
| 2026-10-30 | `t3.small` | `m7i-flex.large` | `db.t3.micro` | `cache.t4g.micro` | 0.2347 | 데모 사양. Redis를 줄이고 AI 메모리를 확보 |

- **apply 전에 확인:** `m7i-flex.large`가 이 계정의 Free 플랜에서 허용되는지 직접 통과한 적은 없다. plan에서는 걸리지 않고 apply에서 실패하므로 콘솔의 EC2 시작 화면에서 "프리 티어 사용 가능" 표시를 먼저 본다. 거부되면 AI를 `t3.small`로 되돌리고 계정 플랜을 검토한다.
- Redis 노드 변경은 `apply_immediately = true`라서 유지보수 시간대를 기다리지 않고 바로 적용된다. 엔진이 같아 교체가 아니라 수정이고 엔드포인트도 그대로다. 몇 분간 연결이 끊길 수 있다.
- EC2 유형 변경은 교체가 아니라 정지 → 유형 변경 → 시작이다. 고정 사설 IP와 AI `/data` 볼륨은 유지된다. 그래도 AI 변경 전에는 데이터 볼륨 수동 스냅샷을 만든다([데이터 보호 가이드](DATA-PROTECTION.md)).

## 비용

월 비용 = Σ(시간당 단가 × 가동 시간) + 월 고정 스토리지.

| 월 고정 항목 | 계산 | $/월 |
|---|---|---|
| EBS gp3 (root 30 + 40 + 30, 데이터 20) | 120 GiB × $0.0912 | 10.94 |
| RDS gp3 | 20 GiB × $0.131 | 2.62 |
| Secrets Manager (app, ghcr, RDS 관리형) | 3개 × $0.40 | 1.20 |
| DLM 스냅샷 7개 (증분, 최대치 가정) | 20 GiB × $0.05 | ≈ 1.00 |
| **합계** | | **15.76** |

EC2를 중지해도 RDS·Redis·FE Elastic IP는 계속 과금된다(시간당 $0.055, RDS도 중지하면 $0.029). BE·AI의 자동 공인 IP는 중지하면 반납된다. ElastiCache는 중지 기능이 없고, RDS는 중지해도 7일 뒤 자동으로 다시 시작된다.

| 운영 방식 | EC2 가동 | 계산 | $/월 | $100 크레딧 | 이전 사양 |
|---|---|---|---|---|---|
| 24시간 상시 | 730h | 0.2347 × 730 + 15.76 | ≈ 187 | ≈ 16일 | ≈ 242 |
| 평일 10시간 | 220h | 0.2347 × 220 + 0.055 × 510 + 15.76 | ≈ 95 | ≈ 32일 | ≈ 197 |
| 시연 직전만 | 40h | 0.2347 × 40 + 0.055 × 690 + 15.76 | ≈ 63 | ≈ 48일 | ≈ 181 |
| 시연 직전만 + 쉬는 동안 RDS 중지 | 40h | 0.2347 × 40 + 0.029 × 690 + 15.76 | ≈ 45 | ≈ 67일 | ≈ 163 |

- 제외: 데이터 전송(인터넷 송출 월 100 GB까지 무료), S3 녹음 용량(GB당 $0.025), Secrets Manager API 호출, Free 플랜 크레딧 차감 규칙.
- 시연·테스트가 없는 시간에는 EC2 3대를 중지한다. 1주 넘게 쓰지 않으면 [데이터 보호 가이드](DATA-PROTECTION.md)의 절차로 정리한다.
- Billing → Budgets에 월 알림(예: $60)을 걸어 크레딧이 예상보다 빨리 줄면 알 수 있게 한다.

## 사양 확정 절차

배포 후 아래 순서로 측정하고 결정을 기록한다.

### 1. 측정 도구

- **스냅샷 수집(읽기 전용):** Infra Actions → **SSM deploy (manual)** → `mode=measure`. 세 인스턴스의 `uptime`, `free -m`, `df -h`, `docker ps`, `docker stats --no-stream`, `docker images`를 출력한다. 비밀값은 출력하지 않는다.
- **CloudWatch 기본 지표**(콘솔): EC2 `CPUUtilization`, `NetworkIn/Out`, `CPUCreditBalance`(`t3`), EBS `VolumeReadOps/WriteOps`. **메모리와 디스크 사용률은 CloudWatch 기본 지표에 없다.** 장기 추이가 필요하면 CloudWatch 에이전트를 별도로 도입해야 한다(이번 범위에는 없다).

### 2. 시나리오와 기록 항목

| 시나리오 | 측정 | 기록 |
|---|---|---|
| A. 유휴 | 모든 인스턴스 `measure` | `available` 메모리, 컨테이너별 메모리 |
| B. AI 첫 기동 | AI 배포 로그 | 이미지 pull + 모델 다운로드 + 헬스 200까지의 시간(헬스 대기 600초 안인지) |
| C. 추론 부하 | 요청을 보내는 동안 AI·BE `measure` | AI 컨테이너 메모리 최대치, 응답 시간, AI vCPU 사용률 |
| D. **CPU 학습** | 학습 요청 후 학습이 도는 동안 AI `measure`(여러 번) | 학습 소요 시간, **학습 중 메모리**, 학습 중 추론 응답 시간 |
| E. FE/엣지 | FE `measure`, CloudWatch | 메모리, CPU 크레딧 잔량 |
| F. 디스크 | 각 인스턴스 `df -h` | root·`/data` 사용률 증가 추이 |

### 3. 판단 기준(제안, 실측 후 조정)

| 지표 | 상향·확장 신호 | 하향 신호 |
|---|---|---|
| `available` 메모리 | 부하 중 총 메모리의 20% 미만으로 떨어진다 / 스왑·OOM 종료 흔적 | 모든 시나리오에서 60% 이상 남는다 |
| CPU | 지속적으로 70% 이상 / 학습 시간이 사용자 경험상 허용 범위를 넘는다 | 지속적으로 20% 미만 |
| `t3` CPU 크레딧 | 잔량이 계속 줄어 0에 가깝다 | |
| 디스크 사용률 | 70% 이상이거나 증가 추세가 뚜렷하다 | |
| AI 헬스 대기 | 600초에 가깝거나 넘는다 → 대기 시간·사양 재검토 | |
| Redis `BytesUsedForCache` (CloudWatch) | 300 MB를 넘는다(`cache.t4g.micro`의 사용 가능 메모리는 약 0.37 GiB) | |

상향할 때의 다음 단계: BE는 `c7i-flex.large`(2 vCPU / 4 GiB, $0.0958/시간), Redis는 `cache.t4g.small`(1.37 GiB, $0.047/시간). 둘 다 apply 전에 Free 플랜 허용 여부를 확인한다.

변경은 변수(`*_instance_type`, `*_root_volume_size_gb`, `data_volume_size_gb`)로 하고, **인스턴스 유형 변경은 정지·재시작을 일으키고 사양에 따라 교체가 될 수 있다.** 교체가 계획되면 apply 워크플로가 `allow_destroy`를 요구하고, apply 후 마지막 성공 배포로 자동 복원된다. AI 인스턴스 변경 전에는 데이터 볼륨의 수동 스냅샷을 만든다.

### 4. 결정 기록

측정 후 `deploy-step.md`의 진행 로그에 다음을 남긴다: 측정 일시, 시나리오, 핵심 수치, 결정(유지/상향/하향)과 근거, 바꾼 변수 값. AI 학습이 BE 응답에 영향을 준다고 확인되면 학습 전용 인스턴스 분리를 새 ADR로 다룬다.

## 확정 전에 하지 않는 것

- 컨테이너 메모리·CPU 상한(`--memory`)은 설정하지 않았다. 실측 후 근거를 가지고 정한다.
- "8 GiB면 충분" 같은 단정은 하지 않는다. 추론 3건 측정만으로는 확정할 수 없다.
